## Shared release and verification rules

- Functions source declares Node.js 22 in `functions/package.json` and `firebase.json`; the quick gate builds TypeScript and analyzes all five Flutter apps. A gate pass proves local source quality only.
- Deploy by explicit function name from the applicable phase manifest. The repository intentionally records live-only functions with no source; a blanket functions deployment can offer their deletion.
- Deploy indexes and rules only after checking the exact client/server dependencies and installed-client compatibility. Source `firestore.indexes.json` and `firestore.rules` are not evidence of live parity.
- Keep API keys and provider credentials in server-managed secrets. F3 distance pricing requires a restricted server-only Routes key with quota/budget monitoring. No secret value belongs in this document or a mobile bundle.
- Local emulator tests must use `demo-*` projects and synthetic identities. No live-read option is inferred from a demo pass.
- Mobile platform readiness is separate from Flutter analysis: signed Android/iOS device journeys, notification receipt/tap behavior, permission denial, app background/resume and store signing need their own evidence.
